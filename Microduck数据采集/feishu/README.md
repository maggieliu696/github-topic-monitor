# 飞书群日报推送

这个目录负责把已经审核通过的日报发送到指定飞书群。它不负责采集 GitHub，也不负责生成研究结论。

完整顺序是：GitHub 采集与分析完成 → 生成并审核 `pilot/output/日报.md` → 本程序转成飞书卡片 → 发送成功后记录内容指纹。相同内容默认不会再次发送。

## 第一次接入

1. 在目标飞书群的“群机器人”中添加“自定义机器人”。
2. 开启“签名校验”，复制 Webhook 地址和签名密钥。
3. 在本机终端执行：

```sh
cd "<当前项目目录>"
bash Microduck数据采集/feishu/configure_macos_keychain.sh
```

脚本会在终端中隐藏输入，并将两项凭证保存到当前 macOS 用户的钥匙串。凭证不会写入项目文件。

## 预览和发送

只生成卡片预览，不访问飞书：

```sh
python3 Microduck数据采集/feishu/send_digest.py --dry-run
```

测试发送当前日报：

```sh
python3 Microduck数据采集/feishu/send_digest.py
```

发送成功后，结果写入 `feishu/state/发送记录.jsonl`，内容指纹写入 `feishu/state/最后发送.json`。重复运行不会再次发送同一份日报；只有确认确实需要重发时使用 `--force`。

## 当前边界

当前项目已将 GitHub 采集、Agent 阅读和日报生成串成日常流程。迁移后必须使用新机器人凭证和当前路径重建定时任务，先用 `--dry-run` 验证，再真实发送。

飞书自定义机器人只能把通知发到创建它的群，不能读取群消息或处理成员回复。日报中的本机文件链接不会发给群成员；正文中的公开 GitHub 链接会保留。

## 当前正式推送目标（2026年10月29日）

每日北京时间9:30推送到正式群；目标保存在本机权限600的 state/delivery.json，优先于旧测试机器人凭证。正式机器人已验证无需签名，发送时不沿用旧密钥。不要在日报或日志中输出Webhook。未来若正式机器人启用签名校验，须同步配置其自己的密钥。测试凭证仅作历史保留，不再作为默认目标。
