# GitHub 增量筛选说明

这一步由 Python 程序完成，不消耗 Agent 阅读 Token。

## 每天怎样比较

程序为每个项目保存一份上次检查状态，主要包括：

- 仓库最后推送时间；
- 仓库资料最后更新时间；
- 默认分支和归档状态；
- Star、Fork 和问题数量；
- README、Issue、评论和版本正文的内容指纹。

再次检查时，程序先比较仓库状态：

1. 状态完全相同：停止处理，不读取历史档案，也不交给 Agent；
2. 只有 Star 等数字改变：写入机械变化记录，不交给 Agent 阅读；
3. 仓库代码或资料有更新：继续读取相关内容，再比较内容指纹；
4. 正文、标题或问题状态确实改变：只把变化片段和少量上下文写入 `agent-review-queue.json`。

Agent 每天只读 `agent-review-queue.json`，再决定是否更新项目记录和日报。全部机械差异另存于 `changes.json`，可供复查。

## 内容指纹是什么

程序把标题、正文、状态、作者、链接和内容类型整理成固定文本，再计算 SHA-256。两次指纹相同，说明这些实质内容没有变化。采集时间等每天都会变化的字段不参与计算，因此不会制造假变化。

## 当前限制

未登录时，GitHub REST API 的公开额度是每个来源 IP 每小时 60 次；认证后，个人账号通常是每小时 5,000 次。程序优先从环境变量读取 Token，没有时从 macOS 钥匙串的 `robotic-harness-github-token` 读取。Token 不写入项目文件。配置脚本为 `configure_github_keychain.sh`。
