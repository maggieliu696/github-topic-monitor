# robotic harness 项目记录与日报

直接打开[阅读入口](output/索引.md)：一份最新日报，以及每项目一篇的可读记录。项目现状、问题和日期更新都在同一篇，来源直接链接原文。

## 怎样维护项目记录

`output/项目记录/` 当前平放41份项目文档。研究步骤读完新资料后，更新正文中的当前情况，再在同一篇末尾追加实际进展和日期；程序不覆盖这些正文，也不因重复运行而修改其资料日期。具体写作规则见[项目记录与日报设计](档案与日报设计.md)。

项目编号、原文快照、变化历史和研究判断版本仍在后台JSON与原始数据中保存，不再生成来源清单、原文全文、完整档案、变化日志等多个Markdown。旧版展示文档已保存为 `output/archive/旧版展示文档_20261026.zip`，需要时可恢复。

## 历史试点重放（不是当前每日流程）

旧试点限定三个项目，默认写入独立的 replay-output；正式日报目录有防覆盖检查。现有程序只处理已取得的资料，不联网、不启动定时任务，也不向团队发送消息。运行及测试命令如下：

```bash
python3 Microduck数据采集/pilot/pipeline.py --output Microduck数据采集/pilot/replay-output
python3 -m unittest discover -s Microduck数据采集/pilot/tests -v
```

默认读取 `input/清洗记录补全.jsonl`、上级 `demo/API原始响应.jsonl` 和 `annotations/`。后台保留原文与父帖、内容版本、结论修订和未知事项；重复资料不制造新进展。来源变化后须重新阅读，不用旧判断冒充已更新判断。程序不自动写项目正文，持续研究与自动写作尚未接入。

## 日报编辑

每次生成前遵守[任务书的语言要求](../调研任务书.md#日报最后的中文润色)，对照[固定认可样稿](../writing-skills/日报风格基准.json)，再应用 Humanizer-zh 编辑本期事实稿。最新成稿保存于 `output/日报.md`，`output/团队日报样例.md` 同步；旧稿保存于 `output/archive/`。

`team_digest.json` 和 `pipeline.py --render-team-run` 目前仍对应早期三个项目的试点。不要用旧试点覆盖当前40项目日报；后续接入自动写作时须使用本期来源和上述语言要求。没有新的重要内容时保留最近一期全文与原日期。
